# v0.1.6

Follow-up release after the v0.1.5 reliability update.

## What Changed

| Area | Change |
| --- | --- |
| Code scanning | Documented the local Codex app path trust boundary directly at the CodeQL-reported `Path` conversion and suppressed `py/path-injection` at that exact line. |
| Codex app path | The guard still accepts only non-empty absolute `.app` paths and verifies the OpenAI Codex bundle id before persisting the value or running native smoke. |

## Why

GitHub CodeQL flagged the conversion from the local operator-provided Codex app
path to `Path`. That value is not executed just because it exists: full guard
paths verify `CFBundleIdentifier == com.openai.codex` before the path is
persisted or used for `codex exec`. This release keeps that validation and
adds an inline CodeQL suppression with the local trust-boundary explanation so
future security scans do not leave a misleading open alert.

## Verification

The same release verification ladder from v0.1.5 was rerun for this commit,
including unit tests, secret scan, public release audit, package build,
download drill, live install with native smoke, and live verifier.
