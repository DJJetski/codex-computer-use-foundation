# v0.1.8

Reliability and public-security follow-up after v0.1.7.

## What Changed

| Area | Change |
| --- | --- |
| Public audit output | Historic marker, email, and secret matches now report only redacted git locations instead of echoing matched content into terminal or CI logs. |
| Native status probes | Guard MCP status probes set `CODEX_CU_LAUNCHER_SKIP_GUARD=1` so read-only probes do not trigger nested launcher `ensure-config` repair. Full `ensure` still runs the repair path before probing. |
| Native tool parity | Guard discovery now requires the complete native MCP tool surface: `list_apps`, `get_app_state`, `click`, `perform_secondary_action`, `set_value`, `select_text`, `scroll`, `drag`, `press_key`, and `type_text`. |
| Native smoke focus | The live Safari smoke now opens its test page with `open -g` and tells Codex to target Safari by bundle id instead of relying on the frontmost app. |
| Dialog safety | The local dialog helper now rejects privacy, security, TCC, network, firewall, and Little Snitch text before any click and no longer clicks `Always Allow` unattended. |
| Security reporting | GitHub issue template security links now point directly to this repository's private advisory and security policy pages. |
| Code scanning | Kept GitHub CodeQL on the repository's default setup instead of shipping a duplicate advanced workflow that conflicts with default setup. |
| Runbook | Added recovery guidance for deleted LaunchAgent or bootstrap files, with the explicit reminder that structural repair is not native success without fresh native smoke and `fallback_used=false`. |
| README SEO | Added exact symptom phrases for Computer Use never working after install and stopping after update. |

## Why

The repository already rejected hidden fallback automation and personal data
leaks, but the audit tooling itself should not print a discovered secret while
reporting that it found one. Status-style probes should also remain diagnostic:
they may inspect the MCP surface, but they should not run the launcher's
repair hook as a side effect. Full native discovery should fail if any expected
Computer Use tool is missing. Live smoke should prove native app targeting
without unnecessarily stealing frontmost focus from the user's current app.
