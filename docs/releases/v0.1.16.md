# v0.1.16

Native MCP transport reset and CodeQL triage release.

## What Changed

| Area | Change |
| --- | --- |
| Native Computer Use | Added `codex-computer-use-guard reset-mcp-transports` for visible `mcp__computer_use__` namespaces that return `Transport closed`. The command force-drops resident `SkyComputerUseClient mcp` processes, records `last-mcp-transport-reset.json`, and makes the next proof step explicit. |
| Thread safety | Updated docs and the canonical Computer Use skill so agents do not treat a green system guard status, Chrome Extension success, or Browser Use success as proof that the already-open native MCP tool handle is alive. The required proof remains `mcp__computer_use__.list_apps` in the active or fresh thread. |
| Browser routes | Kept Chrome Browser Use and in-app Browser Use separate from the native MCP transport reset path. The Chrome force-install and browser-client repair behavior from v0.1.14 and v0.1.15 is unchanged. |
| GitHub security | Triage comments now document the validated local path and argv boundaries behind the remaining CodeQL path/command-injection alerts: OpenAI Codex app paths are bundle-id validated, shell execution is not used, and plugin paths are guard-owned or inside the verified bundled marketplace. |

## Current Local Evidence

This release addresses the case where native Computer Use is visible in a Codex
thread but the active MCP transport is already closed. The reset command can
remove stale resident native MCP processes, but an already-closed in-thread tool
handle may still require a fresh Codex thread. The release therefore strengthens
the repair path and the agent instructions without disguising Chrome Extension
or Browser Use success as native Computer Use success.
