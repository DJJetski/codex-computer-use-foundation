# v0.1.9

Capability-parity and publication clarity follow-up after v0.1.8.

## What Changed

| Area | Change |
| --- | --- |
| Capability parity | Added a public parity document that distinguishes OpenAI Codex app Computer Use, API Computer Use action names, and this repo's exact native MCP tool contract. |
| Background use | Documented that the live smoke proves non-frontmost native app action through Safari by bundle id, while not overclaiming minimized, invisible, off-Space, Terminal, Codex, admin, security, or privacy prompt control. |
| Dialog boundary | Reaffirmed that routine local dialog autopilot is separate from native Computer Use health and must not approve Little Snitch, network/firewall, TCC, privacy, security, account, payment, Keychain, or `Always Allow` prompts unattended. |
| Public package | Included the parity document in the generated public release surface and audit checks so GitHub release readers get the same capability contract as the source repo. |

## Why

OpenAI now documents Codex app Computer Use as a background macOS capability
that can operate graphical apps with its own cursor, while also documenting
approval and safety boundaries. This release makes the repo's public wording
match that upstream contract precisely: repair and validate the native OpenAI
Codex Computer Use plugin surface, do not invent extra tools, and do not hide
security-sensitive dialog automation inside native health.
