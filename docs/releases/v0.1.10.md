# v0.1.10

Dialog-boundary correction after v0.1.9.

## What Changed

| Area | Change |
| --- | --- |
| Little Snitch prompts | Restored a restricted Foundation/Codex network-prompt path for recurring repair-system dialogs after the user has granted local Automation/Accessibility access. |
| Native parity | Kept the boundary clear: this path is not native Computer Use health and does not expand OpenAI's native MCP tool surface. |
| Safety | Generic firewall, privacy, TCC, administrator, password, account, payment, cloud, Keychain, and security prompts remain explicit operator decisions. |
| Public docs | Updated README, security notes, parity docs, install docs, runbook, architecture docs, and the installed skill wording so GitHub readers see the same contract. |

## Why

Some users run Little Snitch. Installing or updating this repair runtime can
trigger recurring local network prompts for Codex Computer Use, SkyComputerUse,
or the Foundation helper scripts. Those prompts are not supposed to be clicked
by native Computer Use as proof of capability, but the separate dialog operator
helper should be able to keep the repair system from stalling after the user has
already granted local automation permission.

This release preserves that behavior without treating generic firewall approval
as native Computer Use parity.
