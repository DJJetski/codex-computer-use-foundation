# v0.1.15

Chrome force-repair file-permission hardening release.

## What Changed

| Area | Change |
| --- | --- |
| Chrome force repair | Tightened temporary file permissions for patched Chrome skill, patched Chrome browser-client, External Extensions metadata, and Native Messaging host manifest writes from owner-readable `0600` files before atomic replace. |
| GitHub security follow-up | Responded to GitHub CodeQL `py/overly-permissive-file` findings raised by the v0.1.14 Chrome force-repair code. |
| Public release package | Included this release note in the sanitized package and updated the README latest-release pointer. |

## Current Local Evidence

The v0.1.15 change is intentionally narrow: it keeps the v0.1.14 Chrome
Browser Use force-repair behavior, but writes local generated repair files with
stricter owner-only file permissions where world/group readability is not
needed.
