# v0.1.7

Documentation release for the public README.

## What Changed

| Area | Change |
| --- | --- |
| README | Restored the early explanation of why native OpenAI Codex Computer Use is different from fallback automation such as Haindy, `cliclick`, AppleScript, Accessibility scripting, Keyboard Maestro, screenshots, and Playwright. |
| README regression coverage | Added a test that keeps the native-vs-fallback explanation visible near the top of the public README and preserves the `fallback_used=false` success condition. |

## Why

The public README should explain the core boundary before users reach the
installer: this project repairs and verifies the official native Codex Computer
Use path. Explicit operator fallbacks can be useful, but they are weaker
evidence for native health because they can depend on coordinates,
frontmost-app focus, extra permissions, browser/profile state, or signals that
Codex cannot treat as native MCP evidence.

## Verification

The release verification ladder was rerun for this docs-only change:

- unit tests

- secret scan

During live verification, duplicate stale native MCP clients were detected and
removed by `codex-computer-use-guard ensure`; the follow-up verifier passed
with all guard health layers true and `fallback_used=false`.
